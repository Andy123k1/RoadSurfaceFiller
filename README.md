# Road Surface Filler

Road Surface Filler creates native surface areas over road pavement and road-associated sidewalks in Cities: Skylines II. It reads loaded `SurfacePrefab` entries, so custom surfaces supplied by Extra Assets Importer or another asset mod can be selected without editing the surface assets.

Open **RoadSurfaceFiller.sln** to work with the existing project in Visual Studio. The official template's publishing profiles and a draft mod-page configuration are included; see [PUBLISHING.md](PUBLISHING.md).

## Performance update: 0.5.15

- Completed surface areas remain visible while replacement geometry is calculated. Unchanged patches retain their native entities; changed patches with the same surface prefab update their boundaries and meshes in place.
- Generation processes at most two roads per frame, with a four millisecond allowance before starting another road and a limit on outstanding native area requests. A single complex road or junction can exceed that allowance.
- Adjacent queued roads share bounded junction geometry caches until another road/rule event invalidates them. Cached patches are copied before paint clipping changes them.
- Rendering restores changed meshes instead of rebuilding every exact-boundary mesh twice per frame. Native completion uses already matched area entities, with the existing periodic scan retained as a fallback.
- Refresh completion logs include elapsed road generation time, the longest road rebuild, retained/updated areas and new native definitions. Timings cover the mod's queued road work, including ECS waits; they exclude subsequent native jobs, GPU work and overall game FPS.

The stable pre-update backup is in `backups/v0.5.14-stable-before-performance-optimization-2026-10-15`; see its `RESTORE.txt`. City saves are managed separately.

## Compatibility and dependencies

- Target game version: **1.6.2f1** (the version installed during implementation). Rebuild against the game assemblies installed on the player's machine after game updates.
- Required: Cities: Skylines II, the official code modding toolchain, and its supported .NET SDK.
- Optional: an asset-provider mod for custom surfaces. No one provider is required; the picker lists loaded `SurfacePrefab` assets from the game world.
- No third-party source code or external runtime packages are included. The mod uses the game's assemblies and native area renderer.

## Build and install

1. Install the official Cities: Skylines II code modding toolchain and .NET SDK using the [official code modding guide](https://www.paradoxinteractive.com/games/cities-skylines-ii/modding/dev-diary-3-code-modding).
2. Configure `CSII_TOOLPATH` and the managed-assembly paths as described by the toolchain setup.
3. From this directory, run:

   ```powershell
   dotnet build -c Release
   ```

   `Mod.props` and `Mod.targets` from the official toolchain run the game's mod post-processor. Use the toolchain's normal deploy or publish action to install the processed mod.
4. Enable Road Surface Filler and any surface-provider mods in the game's mod manager. In a loaded city, open the new road-surface button next to the top-left Info button.

The project imports the toolchain files from `CSII_TOOLPATH`; a matching game/toolchain version is required. The Release build and official post-processing have been verified on this machine. The toolchain's build target also deploys the output to the configured local Mods directory. A successful build does not verify rendering inside a loaded city.

Close the game before installing a build. To compile and post-process while the game is running, use `dotnet build -c Release -p:SurfaceNetworkFilterStageOnly=true`. This puts the complete processed output in `artifacts/v<version>` without changing the installed mod.

### Segment rule presets

1. Open **Segment rules → New segment rule**. A general rule is not required; **Copy to Segment rules** remains available for reuse.
2. Choose the rule's target surfaces and lane handling, then save. No roads change.
3. Choose it in the native road tool's **Surface rule** picker, then draw new roads or use **Replace** on existing roads. Click or drag across roads to apply the preset.
4. Each committed segment receives its own city-saved copy. Use **Tools → Restore vanilla surfaces** to remove this mod's local and city finishes from selected roads, or use **Replace** with **None (vanilla)**.

**Fill bus-lane shoulders** is a separate tool for a quick paved-shoulder extension without replacing other local target settings. It can use the existing custom bus finish or a chosen surface. On bus-only roads the paved terminal cap receives the bus finish too. Raised sidewalks, planting beds, tree strips, active car lanes and bicycle lanes stay excluded.

Presets save with global mod settings and never participate in automatic road matching. Applied copies save with each city in the original v0.4.1 record schema. Native original-edge links transfer existing upgrades when upgrading a road or splitting it with a junction; unrelated new roads do not inherit them. Existing placement/network/elevation filters still apply. Junction pavement priority is controlled in Tools.

### Roundabout pavement boundaries (v0.5.0)

Pavement follows the inner contour of the physical sidewalk, including the recovered mixed highway/street entry taper, so the shoulder between the bike ring and curb receives pavement. Sidewalk exclusion remains independent of the selected sidewalk material and material priority.

The road ribbon's actual triangle footprint is unioned in local double coordinates before subtracting sidewalk, dedicated-lane and planting masks in one pass. Reentrant ribbons can therefore produce compact outside contours without treating every internal triangle as a separate surface. The island cutout and bounded projection volumes remain protected. Use **Rebuild city** after installing to replace previously generated areas. Compilation does not verify the result in a loaded city.

### Junction shoulders and roundabout clipping (v0.5.1)

- Bus shoulder upgrades now reserve and paint the expanded native junction footprint too. Bus-only approaches fill their paved carriageway through the junction, including curb ramps. Mixed roads retain the bus band's shoulder extension. All connected physical sidewalks and planting are excluded even when no custom sidewalk finish is selected. Existing saved upgrades are reused; **Rebuild city** regenerates them.
- Roundabouts use a plane sweep to subtract sidewalk, lane and planting masks from the actual road mesh. Continuous upper/lower boundaries are kept in one area until a real split or join; float-sensitive contour joins can no longer force the first fallback to one surface per triangle. Multi-part ribbons are combined before clipping.
- The roundabout's road-to-sidewalk midpoint height cutoff has been removed. Its geometric sidewalk mask protects the walking footprint, while the normal bounded decal depth reaches the raised asphalt rim up to the curb. The log reports sweep output-area counts and bus shoulder junction coverage for in-game diagnosis.

### Grass/tree upgrades and junction curbs (v0.4.0)

Grass and tree planting strips are excluded from road, sidewalk, bike lane and bus lane surfaces. Version 0.3.10 reads the cross-section of the actual rendered grass material inside each composition piece. The stock `RoadGrass` material and other grass-named materials supply their own native mesh bounds; the piece or road name is not used to classify the whole piece. A grass region remains protected even when its combined piece also contains a pedestrian lane. Version 0.3.9 rejected such pieces and its log reported empty grass masks. Grass/tree gaps without a usable grass mesh use the native walking route's inner edge, rather than a previously expanded sidewalk band. Tree-only verges retain their original finish. These exclusions apply with both lane separation switches off. Native planting at nodes is subtracted from every approach's overlays; approach gaps are not extended through intersections where the planting ends.

All upgraded profiles discard master/virtual traffic groups when identifying the physical curb. Mixed road/sidewalk pieces contribute the paved raised plateau beside the adjacent traffic lane. This plateau is read from upward-facing mesh triangles at the piece's middle cross-section, with its actual deck height. Encoded shader normals do not determine its bounds. Contiguous faces at the same deck height are joined; a narrow curb lip cannot replace a wider walking plateau. Raised material plateaus take priority over lane-only fallbacks, and the narrowed candidate must still contain the pedestrian lane center. Grass is then removed from the sidewalk bands before applying side selection. The log records native material names, paved widths/heights and final planting bounds for a limited number of profiles.

Version 0.3.11 retains the native walking envelope at the outside edge of the raised plateau. Some native pieces lower that rim by 0.2 m; the lowered part still belongs to the sidewalk. The reported plain 24 m road had 4 m walking envelopes but only 2 m painted widths, while its grass profile stopped at 11.6 m instead of the 12 m outer boundary. Extending only the outside edge includes these rims without moving the inner curb into traffic or planting. The existing projection depth covers the lower receiver.

Version 0.3.12 maps material profiles and fallback mesh vertices with the same lateral orientation as the native renderer's `GenerateCompositionMesh`: mesh X is negative by default and positive for an inverted section. Lane positions retain their separate native convention. The reported 24 m grass-upgraded road has a right-side piece at +9 m with local grass at 0..2.4 m; its rendered planting lies at 6.6..9 m, with the walking surface at 9..12 m. The previous orientation protected 9..11.4 m instead, leaving only a narrow painted outside strip. Both pavement and grass profiles now share the corrected transform on both road sides, while retaining the outside rim coverage added in 0.3.11.

Version 0.3.13 retains the wider native sidewalk curb at intersection mouths where approach planting ends in a paved cap. The reported medium road changes from a 3 m edge walkway to a 5 m node sidewalk; the small road changes from 3 m to 4 m. Tapering from the narrower edge walkway left triangular caps unpainted. The inner mouth now follows the native node curb when the widening replaces an approach planting strip and contains no node planting. The outer edge still joins the segment sidewalk, native corner endpoints still match, and actual planting remains excluded. This changes the existing sidewalk ribbon rather than adding separate cap areas. Both road orientations and asymmetric upgrades use their own composition bounds.

Version 0.3.14 corrects the planting-cap condition that prevented this path from activating in 0.3.13. The node's material plateau includes the curb lip as well as the former grass footprint, so its complete widening is larger than the grass alone. A widening overlapping the terminated bed now retains the native node curb, while actual node planting still prevents that expansion. Final sidewalk widths are logged for node compositions as well as edges.

Planting exclusions also follow the isolated paved curb faces adjoining the grass within the same native piece, including its lower rim. Physical traffic lanes and pedestrian envelopes stop this extension, preserving actual carriageways and walking surfaces. The reported small grass piece has native grass at local 0.5..1.9 m and curb faces at 1.9..2.1 m and 2.1..2.5 m. Protecting this connected curb removes the separate 0.6 m road overlays logged beside the bus lanes. Bounds come from the native mesh rather than a fixed setback. The same exclusion applies to every surface target.

Version 0.4.0 distinguishes the raised planting curb from its lower asphalt rim. Only adjacent paved faces above the physical driving deck extend the planting exclusion. The lower rim receives road or lane pavement again, restoring the thin missing road strip reported on grass-upgraded roads while leaving the raised curb and grass native. The resolved paved junction caps retain their 0.3.14 geometry.

Material slots are continuous across all meshes in a geometry asset, following `NetMeshHelpers.CacheMeshData`; they do not restart at zero for each mesh. The native grass asset has a separate second mesh/material. Reading that mapping correctly protects its grass footprint directly. The mod prefers the game's cached `MeshVertex`, `MeshIndex` and `MeshMaterial` buffers, whose indices already include source mesh vertex offsets. This avoids requesting compressed attributes after the renderer has released them. An incomplete profile is not cached permanently. Grass receiver footprints accept either winding; pavement plateaus use upward faces.

Road overlays on segments, ordinary junctions and roundabouts retain the projection ceiling below raised sidewalk receivers added in 0.3.9. Shared junction fills use the most restrictive connected curb ceiling. Planting flags and piece positions are included in rebuild signatures independently of the bike/bus switches.

### Separate bike and bus lane surfaces (v0.4.0)

1. Edit a rule and choose its road category or exact road type. **Separate bike lane surfaces** and **Separate bus lane surfaces** are options inside that rule; new rules default both to off. The former global settings are used only to migrate existing rules.
2. Off uses road pavement. On reserves the detected lane footprint on matching roads. Leave its target unchecked or choose **Original lane finish** to keep the game's finish visible. Grass, sidewalks and native lane meshes remain protected by their physical bounds.
3. Check **Bike lanes** or **Bus lanes** under **Apply surface to** to open that target's surface picker. Checking a lane also turns on its separation option. Choose its own surface alongside the road and sidewalk surfaces in the same rule. Switching separation off retains the saved lane choice for later use.
4. Lane settings use the most specific enabled matching rules: exact road type, category, then all roads. An enabled switch in any equally specific matching rule reserves that lane. A new specific rule with separation on and no lane material retains the original finish instead of borrowing a broader rule's lane material. Disabling, deleting or saving a rule refreshes placement within the existing scope; paused placement waits until resumed.

Detection reads the final native lane composition after road upgrades. Bike lanes use `LaneFlags.BicyclesOnly` or an exclusively bicycle `CarLaneData.m_RoadTypes`; bus lanes use road `LaneFlags.PublicOnly`. Mixed car/bicycle traffic is not classified as a bike lane. Master/virtual routing groups and crossings are excluded. Widths, lateral positions and heights come from the actual lane metadata, not road or asset names. Road paint is split around reserved strips rather than layered over them. Raised bicycle tracks may sit outside the ordinary carriageway bands; their own native footprint is used, excluding sidewalks.

Lane surfaces follow native curved road boundaries. At junctions, the mod includes the authored bicycle bands in the node composition mesh, rendered secondary crossing/corner lanes and dedicated driving lanes. Composition bands follow the native side curves and vertex matching. Dedicated driving paths use the physical lane width and native width offsets; bicycle paths require both bicycle-only endpoint flags and exclude unsafe routes. This includes diagonal crossings between bicycle lanes while excluding transitions into general traffic lanes. Driving paths do not require a separate gameplay mesh: their green/red finish can be part of the node composition. Geometry-only secondary strips still use the native mesh visibility conditions. A strip uses its connected source road's lane rule. Scope and road/elevation filters apply to that source. Each strip belongs to one source road and regenerates with it.

Roundabouts reconstruct a continuous bicycle ring from the native circulation anchors and physical lane width. The game's `PresetCurve` adjusts Bezier handles for traffic flow, so the painted circle does not require every point of a navigation curve to lie at an identical radius. Angular coverage is measured across complete arcs, including the intervals between samples. Native curve samples provide the deck elevations. Four joined arc areas cover the circle, including gaps in the navigation graph at a non-bicycle approach. The selected connected bicycle road supplies its rule; otherwise the widest connected bicycle road does. Larger roundabouts draw the pavement directly as inner and outer curved bands sharing the bicycle ring's boundary. Entry/exit connectors follow dedicated native paths. Small roundabouts retain their bounded geometry repair. Lane mask fragments are joined into simple contours wherever possible, avoiding a separate surface area for every clipped triangle while leaving reserved lane holes open.

### Apply to individual segments

1. Open the top-left **Road Surface Filler** panel and create a preset under **Segment rules**.
2. In the native road tool, select the preset using **Surface rule** to style newly drawn roads.
3. Use native **Replace** with the same picker to apply another preset to existing segments. A surface-only replacement can use the same road type.
4. Choose **None (vanilla)** with Replace to restore individual segments, or use **Tools → Restore vanilla surfaces** to select several segments and apply the restoration together.
5. **Tools → Fill bus-lane shoulders** also supports selecting multiple segments. Junction shoulder connections require both connected roads to enable shoulder filling.

Applied segment overrides save with the city and take priority over its applied city-rule snapshot. Native split/replacement fragments retain their original applied styles. The remaining elevation and sidewalk settings still apply.

### Choose pavement at a junction or roundabout

1. Select a connected road with the Info tool, near the junction you want to change.
2. Open the top-left **Road Surface Filler** panel. Check the junction pavement display. **Nearest junction** or **Other end of road** chooses which end of that segment to change.
3. Press **Cycle junction surface** to apply the next connected road type's active pavement rule. Each click switches the surface and updates the display.
4. **Use selected road** directly applies the selected road's pavement, including highway rules when a highway is selected. **Restore automatic** removes the local preference. These actions are available in the rule manager's **Tools → Junction surface** section.

Connected segments rebuild automatically. The selected pavement is saved with the city in a separate junction record. Adding, splitting or replacing connected roads retains that exact surface; changes to the source segment's random material seed cannot switch it. Native replacement nodes recover the saved choice from the tool's original-node link, with a fallback restricted to the same position and elevation. Existing preferences migrate when their source road and surface are available. Sidewalk materials, physical curb boundaries, roundabout perimeter and island cutout keep their existing behavior. Choose another surface or use **Restore automatic** to change the saved pavement. If its asset is unavailable, the preference is retained. A completely deleted junction's record is removed after the native apply grace period.

## Known limits

- The mod identifies non-crosswalk pedestrian lanes, then reads the raised top of the authored sidewalk mesh to locate the curb. A side piece can contain both sidewalk and asphalt shoulder; only the sidewalk plateau receives the sidewalk material. If mesh data is unavailable, the pedestrian lane's inner edge is used as the curb and its band is extended only toward the outside. Shared road/pedestrian lanes and parking lanes are treated as road pavement. Standalone pedestrian paths are excluded because they do not have road prefab data.
- The game does not expose a reliable separate service-road marker, so road-prefab service layouts are treated as roads.
- Elevated and tunnel filtering uses network elevation together with prefab geometry flags. Custom roads with a deck offset that differs from their lane heights may need a larger projection depth. Decal receiver masks still come from the selected surface asset.
- Edge areas follow the game's rendered `EdgeGeometry` boundaries and stop at its actual junction mouths. Road pavement extends across shoulders and parking space to sidewalk/median boundaries. At ordinary junctions, material boundaries interpolate between each native side segment's outer and inner curves using the composition's vertex-match offsets and the junction's matching targets. The center fill curve is used for pavement reaching the middle, rather than as a cross-section for sidewalk offsets. Adjoining patches share resolved corner positions and connect to the edge ribbon's exact material endpoints. This avoids normal offsets pinching away acute corner bands or leaving triangular mouth gaps. Curved material boundaries are sampled to a 1 cm chord tolerance, with at least 16 intervals per junction side.
- Junction compositions have no `NetCompositionLane` buffer in the game. The mod reads their authored `NetPieceLane` data and uses approaching road lanes as a fallback; their native geometry is still used for placement. The log records node layout ranges and how many intersection/roundabout patches were queued, making a skipped junction visible in diagnostics.
- Road/sidewalk ribbons provide explicit triangles instead of depending on native area ear clipping, which can reject narrow tapers and concave approaches. These triangles are restored after native geometry, before area spatial indexing, and before GPU batching. Generated areas use a private rendering copy of the selected surface; the provider's asset is not modified.
- Version 0.2.12 removes the full-footprint junction experiment from version 0.2.11 after the user reported sidewalk material inside the carriageway. Ordinary junctions again use physical road and sidewalk bands. Mixed junction pavement uses a curb-bounded shared outline, clipped to branch cutoff lines and owned by the lowest-index eligible edge. Same-prefab junctions, partial segment scope, new-segments-only placement, medians, and highway junctions retain approach-owned ribbons. The main road continues to supply the common junction material choice.
- Ordinary road bodies and junction pavement use the configured projection depth without the additional road/sidewalk height caps introduced in version 0.2.10. These areas retain their geometric curb masks. Shared fills and clipped boundaries retain horizontal renderer compensation; cut pieces discard unused nodes before cleanup. Compensation is rejected when predicted error exceeds 2.5 cm and the original footprint has a bounded native corner reach. Existing roundabout projection separation and the small-roundabout guard remain in place.
- Branch cutoffs clip original ribbon triangles and retain interpolated heights. Connected components become separate native areas; invalid topology uses perimeter clipping with a bounded diagnostic. Raised sidewalk pieces inside a branch cutoff use the main sidewalk material within the original narrow sidewalk footprint, with a projection minimum above the main road. Pieces outside retain the branch material. Empty opposite-side bands are skipped before corner recovery.
- Version 0.2.12 records bounded coordinate diagnostics for up to four mixed ordinary junctions: native side/middle curves, vertex-match offsets and targets, band heights, final patch nodes and triangles, and changes in node positions during native materialization. These records go to `SurfaceNetworkFilter.log`; no additional diagnostic file is created. They distinguish a missing footprint from an incorrect projection height or changed native node ordering. Up to 48 patch records and 48 materialization records are emitted per city load.
- Version 0.2.13 addresses artificial borders between generated surface areas, including the long strips visible along alleys and seams at junction mouths. The native area renderer normally adds rounding, edge shading, noise and fading to each polygon. Generated overlays use a private prefab with the minimum native roundness of 0.01, zero edge normal and zero edge noise. For a surface, the native border parameter falls from 0.375 m at default roundness to 0.0075 m. Textures, color, UV scale, opacity, receiver mask and the asset's fade convention are copied. Legacy custom materials receive their own material copy. Geometric curb masks and existing roundabout repair logic remain in use, and every generated overlay receives horizontal boundary compensation.
- Overlay prefabs have stable names and are registered before native prefab initialization and at game preload, so saved generated areas can resolve their renderers. Rendering copies are excluded from this mod's picker and have no extra placement menu entry. Placement waits until the native area archetype is initialized. The log records the original selected asset's border settings and the overlay settings.
- Version 0.2.14 corrects the renderer regression in 0.2.13. Disabling edge noise now sets only its strength to zero while retaining a positive scale in the native supported range of 0.01–10, including for legacy materials. The previous build incorrectly zeroed both values. All authored RenderedArea fields, including external texture asset references and shader version, are explicitly copied from the selected surface before applying the overlay border adjustments. The log reports the corrected noise values and reference preservation. The user confirmed that surfaces draw correctly and the road and junction gaps are fixed in 0.2.14.
- Version 0.2.15 adds a saved pavement source per junction and roundabout, separate from the physical geometry reference. It also corrects automatic alley-to-highway priority and adds a native-mouth cutoff for shallow alley merges. Rendering and roundabout geometry retain the 0.2.14 handling. These additions require in-game visual confirmation.
- Roundabouts use the native curved perimeter. Road vertices pair with matching radial samples around a circumscribed island boundary, including the approach mouth, so the ring does not depend on triangulating one large concave polygon. Sidewalks follow the outside perimeter. Internal median pedestrian bands are excluded. Unusual custom pieces, sharp curves, and noncircular central objects may require further adjustment; a material's edge fade can expose seams between separate areas.
- Roundabout polygon tips with an angle below approximately 14 degrees are shortened with a bevel of at most 12 cm. Only the adjoining local triangle is split. This prevents the native decal renderer's corner expansion from magnifying thin return tips into long spikes, especially around small islands. Surface assets and their renderer settings remain intact.
- Small roundabouts (native island radius up to 4.01 m) use a replacement guard in version 0.2.9. The earlier 12 cm bevels could create sub-millimetre edges and additional unstable corners: the user's log showed native expansion still reaching roughly 50–70 m after correction. The replacement removes boundary nodes unused by the ribbon triangles, splits folded strips into simple areas, and removes any remaining unstable tail vertex before rebuilding the polygon mesh. It measures each result with the game's `AreaUtils.GetExpandedNode` function and continues until corner reach is at most 75 cm or twice the material's ordinary expansion. Degenerate slivers are omitted instead of passing an unsafe area to rendering. The final native nodes are checked again, and previously repaired stable areas are retained. Medium and larger roundabouts keep their existing geometry handling.
- Small-roundabout pavement ribbons also split wherever an approach chord enters the center island. Each remaining run is sampled at angular intervals of at most 1.875 degrees and uses a fixed circumscribed island radius. Version 0.2.9 additionally splits when the outside perimeter reverses its direction around the island, so the radial strip does not fold over itself. Sidewalk ribbons split at folded offset cells as well. Disconnected runs are separate native areas. This avoids enlarging the island radius based on an angular jump across discarded samples, which could push inner road vertices outside the road. The island remains excluded and the native outside perimeter is retained.
- Repaired small-roundabout areas also use per-area horizontal expansion compensation. An inverse offset is accepted only if its predicted maximum boundary error is at most 2.5 cm. Otherwise the renderer uses the already bounded source polygon. The log records the repair's before/after reach, removed tail nodes, suppressed slivers, and compensation fallback. Existing unsafe saved areas that cannot be repaired are deleted; rebuilding regenerates their approach as the new split ribbons.
- Areas do not cut around lane markings, building lots, utilities, or terrain features. Road markings are subject to the selected material's native decal behavior.
- Surface texture projection and orientation are left to the selected `SurfacePrefab` and the game's native area renderer; this mod has no separate per-segment texture rotation control.
- The user confirmed the highway-connected roundabout fix and the small-roundabout repair in version 0.2.9. Junction gaps remained after version 0.2.12, with strips also visible along connected road bodies. The rebuilt log's 48 sampled meshes completely cover their contours (area difference below 0.000001 square metres), all triangles have positive orientation, and native materialization preserves the generated coordinates. The installed game code applies border effects separately to those contours. Version 0.2.13 addresses that rendering behavior; its visual result still requires in-game confirmation. No automated implementation tests or live-game tests were run.

## Troubleshooting

- **No surfaces appear in the picker:** confirm the asset provider and its content are enabled in the mod manager, load a city, then press **Refresh surface list**. The picker only lists assets registered as `SurfacePrefab`.
- **A selected surface is unavailable:** enable its provider, refresh the catalog, confirm the selection, and use **Rebuild current city**. Existing generated areas are left in place while an enabled selection is missing.
- **No area appears after refresh:** check that the road prefab has `RoadData`, a usable lane composition, and a loaded `SurfacePrefab` selection. Check the in-game status field and mod log for timed-out area requests.
- **An area exists but does not texture a road:** the selected surface's `RenderedArea` decal mask must include `Roads`. The mod logs the selected mask and warns about a terrain-only mask or a prefab marked `HiddenIngame`. Completion tracking waits for a permanent area with nonempty triangles.
- **Surface placement is imperfect at an intersection or on a custom road:** press **Rebuild current city** after installing an updated build. The log reports use of native boundaries and the first detected roundabout's island radius. Include screenshots and `SurfaceNetworkFilter.log` when reporting a custom layout that still needs adjustment.
